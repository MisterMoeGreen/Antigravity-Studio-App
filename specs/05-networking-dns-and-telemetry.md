# Specification 05: Networking, DNS & Telemetry Systems

## 1. The Glibc vs. Android Bionic DNS Problem & Go Runtime Resolution

### The Architectural Issue
Android Bionic libc does not use `/etc/resolv.conf`. Instead, Android resolves DNS queries by sending IPC messages over a UNIX domain socket to Android's system daemon `netd` (or `system/netd/resolv`).

In contrast, **`agy.va39` and `libresolv.so.2` are glibc binaries**. They read `/etc/resolv.conf` directly. Furthermore:
1. **Termux Glibc Configuration**: Termux's `glibc` is compiled with `--sysconfdir=/data/data/com.termux/files/usr/glibc/etc`. After our 10-character binary replacement (`com.termux` $\rightarrow$ `ai.agy.app`), `libglibc_c.so` and `libglibc_resolv.so` look for:
   ```text
   /data/data/ai.agy.app/files/usr/glibc/etc/resolv.conf
   ```
2. **Go Pure-Go DNS Resolver**: By default, Go's `net` package bypasses C library resolver routines and issues raw UDP syscalls (`svc #0`). On Android, this pure-Go resolver cannot locate Android DNS servers.

### The Combined Solution
1. **Dynamic DNS Watcher**: `AgyForegroundService` registers a `ConnectivityManager.NetworkCallback` that updates `/data/data/ai.agy.app/files/usr/etc/resolv.conf` on any network change (Wi-Fi $\leftrightarrow$ Cellular $\leftrightarrow$ VPN).
2. **Glibc Config Symlink**: `EnvironmentBootstrapper` creates the symlink:
   ```text
   /data/data/ai.agy.app/files/usr/glibc/etc  ->  /data/data/ai.agy.app/files/usr/etc
   ```
   Ensuring Glibc's `getaddrinfo()` immediately finds the active `resolv.conf`.
3. **`GODEBUG=netdns=cgo`**: Exported into `server.py` and inherited by `agy.va39`. This forces Go's runtime to delegate all DNS lookups to Glibc's `getaddrinfo()`, which reads our dynamic `resolv.conf` cleanly.

```kotlin
private fun registerDnsWatcher() {
    val cm = getSystemService(Context.CONNECTIVITY_SERVICE) as ConnectivityManager
    val request = NetworkRequest.Builder()
        .addCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET)
        .build()

    val callback = object : ConnectivityManager.NetworkCallback() {
        override fun onLinkPropertiesChanged(network: Network, linkProperties: LinkProperties) {
            val servers = linkProperties.dnsServers.mapNotNull { it.hostAddress }
            val activeDns = if (servers.isNotEmpty()) servers else listOf("8.8.8.8", "1.1.1.1")
            
            val content = StringBuilder("# Dynamic DNS generated by Antigravity Studio\n")
            activeDns.forEach { dns ->
                content.append("nameserver $dns\n")
            }
            content.append("options timeout:2 attempts:3\n")

            val resolvFile = File("/data/data/$packageName/files/usr/etc/resolv.conf")
            try {
                val tmpFile = File("${resolvFile.absolutePath}.tmp")
                tmpFile.writeText(content.toString())
                tmpFile.renameTo(resolvFile)
            } catch (_: Exception) {}
        }
    }
    networkCallback = callback
    cm.registerNetworkCallback(request, callback)
}
```

## 2. Dynamic Port Selection & Conflict Prevention

### The Problem
If the user also runs Termux `agy-web` on the device, both applications default to `127.0.0.1:8081`. The second process fails with `java.net.BindException: Address already in use`.

### The Solution
`AgyForegroundService` checks if `8081` is available; if blocked, it falls back sequentially through `8082`, `8090`, and `8091`. The chosen port is published via Kotlin StateFlow `readyPortFlow`:

```kotlin
fun pickAvailablePort(preferred: Int, fallbacks: List<Int>): Int {
    for (port in listOf(preferred) + fallbacks) {
        try {
            java.net.ServerSocket(port).use {
                return port
            }
        } catch (_: Exception) {}
    }
    return java.net.ServerSocket(0).use { it.localPort }
}
```
The active port is passed as an environment variable (`AGY_WEB_PORT`) to `server.py` and consumed by `MainActivity` to point the `WebView` to the exact matching URL.

## 3. Battery & Thermal Hardware Telemetry Bridge

### The Problem
On Android 12+ (API 31+), SELinux policy `untrusted_app` strictly blocks applications from reading `/sys/class/power_supply` and `/sys/class/thermal`:
```text
avc: denied { read } for comm="python3" name="capacity" dev="sysfs" ino=... scontext=u:r:untrusted_app:s0 tcontext=u:object_r:sysfs_batteryinfo:s0 tclass=file
```
When `server.py` queries `/sys/class/power_supply/battery/capacity`, it catches `PermissionError: [Errno 13] Permission denied`.

### The Solution
`AgyForegroundService` registers standard Android `BatteryManager` and `PowerManager` listeners and writes hardware telemetry to `/data/data/ai.agy.app/files/usr/tmp/android_telemetry.json`:

```kotlin
private fun registerTelemetryBridge() {
    val filter = IntentFilter(Intent.ACTION_BATTERY_CHANGED)
    val receiver = object : BroadcastReceiver() {
        override fun onReceive(context: Context, intent: Intent) {
            val level = intent.getIntExtra(BatteryManager.EXTRA_LEVEL, -1)
            val scale = intent.getIntExtra(BatteryManager.EXTRA_SCALE, 100)
            val status = intent.getIntExtra(BatteryManager.EXTRA_STATUS, -1)
            val tempTenths = intent.getIntExtra(BatteryManager.EXTRA_TEMPERATURE, 0)
            val isCharging = status == BatteryManager.BATTERY_STATUS_CHARGING ||
                             status == BatteryManager.BATTERY_STATUS_FULL

            val batteryPct = if (scale > 0) (level * 100) / scale else level
            val tempC = tempTenths / 10.0

            val json = org.json.JSONObject().apply {
                put("battery_pct", batteryPct)
                put("charging", isCharging)
                put("temp_c", tempC)
                put("timestamp", System.currentTimeMillis() / 1000)
            }

            try {
                val outFile = File("/data/data/$packageName/files/usr/tmp/android_telemetry.json")
                outFile.writeText(json.toString())
            } catch (_: Exception) {}
        }
    }
    batteryReceiver = receiver
    registerReceiver(receiver, filter)
}
```

### Server.py Telemetry Fallback Integration
In `server.py`, `get_android_hardware_telemetry()` reads this JSON bridge first:

```python
def get_android_hardware_telemetry() -> dict:
    telemetry_json = Path(os.environ.get("TMPDIR", "/tmp")) / "android_telemetry.json"
    if telemetry_json.exists():
        try:
            with open(telemetry_json, "r", encoding="utf-8") as f:
                data = json.load(f)
                return {
                    "battery": data.get("battery_pct"),
                    "charging": data.get("charging"),
                    "thermal_temp": data.get("temp_c"),
                    "thermal_status": "NORMAL" if (data.get("temp_c") or 0) < 42.0 else "THROTTLED"
                }
        except Exception:
            pass
```
